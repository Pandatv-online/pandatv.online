# Безопасность Panda TV

## 🔴 Инцидент: токен Telegram-бота в клиентском коде

**Что было.** В `PandaTV/js/main.js` обработчик формы подписки содержал
захардкоженные токен бота и `chat_id`:

```js
const telegramToken = "7509062095:AAHq...";   // удалено
const telegramChatId = "7405005534";           // удалено
fetch(`https://api.telegram.org/bot${telegramToken}/sendMessage`, ...)
```

**Почему это критично.** `main.js` отдаётся браузеру каждому посетителю.
Токен был виден через «Просмотр кода страницы», DevTools → Network и в
поисковой выдаче по коду. С этим токеном посторонний может:

- читать все входящие сообщения бота (то есть все заявки клиентов: имена,
  телефоны, email, страна, тариф);
- писать от имени бота во все чаты, куда он добавлен;
- менять имя, описание и аватар бота;
- переставить webhook на свой сервер и незаметно перехватывать заявки;
- заспамить чат или сломать бота (`deleteWebhook`, `logOut`).

Утечка персональных данных клиентов из ЕС — это ещё и нарушение GDPR.

**Что исправлено в коде.** Токен и `chat_id` убраны из `main.js`. Заявка
уходит одним запросом на `LEAD_ENDPOINT` (сейчас — Formspree, публичный по
своей природе эндпоинт: он принимает заявки, но ничего не отдаёт).

### Что нужно сделать вручную — обязательно

Удаления строки из файла **недостаточно**: токен уже скомпрометирован и
остался в истории git.

1. **Отозвать токен прямо сейчас.** В Telegram: [@BotFather](https://t.me/BotFather)
   → `/mybots` → выбрать бота → *API Token* → **Revoke current token**.
   Старый токен перестаёт работать мгновенно.
2. **Проверить бота на следы вмешательства:** `/mybots` → *Bot Settings*
   (имя, описание, команды) и вызвать `getWebhookInfo` с новым токеном —
   если там стоит чужой URL, снять его через `deleteWebhook`.
3. **Новый токен хранить только на сервере.** Пошаговая инструкция —
   [`worker/README.md`](worker/README.md): готовый Cloudflare Worker
   принимает заявку с сайта и сам отправляет её в Telegram и на почту.
   Токен задаётся командой `wrangler secret put` и хранится на стороне
   Cloudflare — в репозиторий, в `wrangler.toml` и в браузер посетителя он
   не попадает. После деплоя поменять `LEAD_ENDPOINT` в
   `PandaTV/js/main.js` на URL воркера.

   Новый токен нельзя пересылать в переписке, в issue или в коммите —
   всё это либо публично, либо становится публичным. Он вводится ровно
   один раз, в терминале, на шаге 3 инструкции.
4. **История git.** Токен остаётся в старых коммитах (`a343bb6`) навсегда,
   даже после удаления из текущей версии. После отзыва токена он безвреден,
   поэтому переписывать историю не требуется. Если всё же хочется вычистить —
   `git filter-repo` или BFG Repo-Cleaner с последующим force-push (учтите:
   это ломает все существующие клоны и форки).
5. Включить в репозитории **Settings → Code security → Secret scanning**
   и **Push protection**, чтобы GitHub блокировал такие коммиты заранее.

## Правило на будущее

Всё, что попадает в `PandaTV/` — публично. В клиентском коде не должно быть
ни токенов ботов, ни API-ключей, ни паролей, ни приватных webhook-URL.
Любой секрет живёт на сервере (Cloudflare Worker, serverless-функция,
бэкенд) и вызывается фронтендом через собственный эндпоинт.

Публичные по назначению идентификаторы (Formspree form ID, Google Analytics
measurement ID, reCAPTCHA site key) в клиентском коде допустимы.

## Подделка почты с домена

У `pandatv.online` не настроены SPF и DMARC — значит письма «от вашего домена»
может рассылать кто угодно, включая фишинг вашим же клиентам. Записи, которые
это закрывают, и предупреждение о том, когда их ставить нельзя, — в
[`DNS.md`](DNS.md).
